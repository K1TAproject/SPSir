# 生成与安装手机试用包

当前版本为 0.4.3，支持 Android 8.0（API 26）及以上。

## 在当前电脑生成 APK

双击项目根目录的 `build-apk.cmd`。看到 `BUILD SUCCESSFUL` 后，安装包位于：

```text
D:\SPSir\app\build\outputs\apk\debug\SPSir-0.4.3.apk
```

也可以在 PowerShell 中运行：

```powershell
cd D:\SPSir
.\scripts\Build-Apk.ps1
```

该入口只构建 APK，不启动模拟器，也不向手机自动安装。初次在另一台电脑构建前，需要按 README 配齐 JDK、Android SDK 与 Gradle 依赖。

## 安装到手机

1. 将 `SPSir-<版本号>.apk`（当前为 `SPSir-0.4.3.apk`，文件名自动使用构建版本）通过 USB 文件传输等方式复制到手机。
2. 在手机文件管理器中打开 APK。
3. 如果系统提示当前文件管理器不允许安装应用，按提示仅为该来源开启“允许安装未知应用”，然后返回继续安装。不同品牌的设置名称可能不同。
4. 安装后打开“SPSir”。手机账本初始为空；它不会自动同步电脑模拟器的数据。
5. 若需要迁移模拟器账本，先在模拟器应用的“工具”中导出备份，把 JSON 文件复制到手机，再在手机应用中选择该文件恢复。

## 后续更新

修改代码后再次运行 `build-apk.cmd`，将新 APK 复制到手机并覆盖安装。相同应用 ID、相同签名的更新会保留应用数据；更新前仍建议从“工具”导出备份。

若提示签名冲突，不要直接卸载已有应用：先导出账本。卸载会删除应用内数据及覆盖前副本。换电脑构建可能使用不同的调试签名，需要保留原签名或在备份后重新安装并恢复。

## 这个包的用途

这是自动带调试签名的 APK，可以直接在个人手机试用，无需申请应用商店账号。调试版允许开发调试，不作为公开正式发行包。

正式发行时再配置独立 release 签名、提高版本号并验证发布包；签名文件和密码应妥善保管，不提交到 GitHub。本次未创建正式发布密钥。

代码版本与安装包分别保存：GitHub 管理源码，APK 位于已忽略的构建目录，不会随普通 Git 提交上传。

## 保护现有安装的签名

当前本机脚本使用的调试签名位于 `.tools/android-user/debug.keystore`。请将它单独备份到可信的离线位置；该目录被 Git 忽略，推送源码不会备份签名。不要将签名文件上传到仓库，也不要删除后重新生成。

换电脑时除源码、SDK 和 JDK 外，还需恢复同一个签名文件，并核对新旧 APK 的证书摘要，才能保持覆盖安装。将来切换正式签名应先单独规划账本迁移，不能直接假设不同签名也可以覆盖更新。

当前的备份导出、导入和覆盖前副本统一限制为 20 MiB（20 × 1024 × 1024 字节）。超限时会明确拒绝；导出在打开目标文件前检查，恢复在删除任何数据库记录前检查。不要为缩小备份而删除账本数据。大于此限制的账本需要后续支持流式备份，当前版本不会输出其无法恢复的成功备份。

0.4.3 会自动将数据库迁移到版本 4，保留原记录。新版完整备份格式为 3，旧版应用不支持恢复该格式；请在升级前保留一份旧版备份，不要直接降级覆盖安装。文字账单不属于完整备份。
