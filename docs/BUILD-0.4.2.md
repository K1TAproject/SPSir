# 0.4.2 稳定性与性能优化

日期：2026-10-05。版本：0.4.2，versionCode 7。

## 改动范围

- 导出、导入和覆盖前安全副本共用 20 MiB 容量规则。导出先完成编码及容量检查，再打开目标文件；安全副本不合格时不会执行覆盖数据库的 SQL。
- JSON 改为紧凑格式，仍使用备份格式版本 2，继续读取版本 1 和带缩进的旧备份。金额直接验证最小单位整数，复用正则与预设分类索引，减少重复转换和对象创建。
- 工具页、事件详情、底部标签和筛选结果接入系统返回操作。
- 普通记账、公共开支、新建事件及成员编辑在有未保存输入时确认放弃。未修改的记账表单直接关闭。
- 表单使用可保存状态容器，在状态重建后等待数据库加载，避免先创建空白表单覆盖草稿。取消或保存后清理旧表单状态。
- 数据库变化触发后台事务快照，原子读取分类、事件、流水、隐藏分类和公共费用，避免分别收集多条 Flow 时混用新旧数据。
- 缓存按月筛选、按日/事件分组及公共事件成员余额；事件卡片和详情复用分摊结果。普通录入表单拆到 `EntryEditor.kt`，保持原有布局和数据接口。
- 错误提示区分保存、读取、导出、恢复操作；异常日志仅记录类型和堆栈，不写异常消息、SQL、路径或账本内容。
- 数据库仍为版本 3，未新增字段、业务功能或依赖。应用 ID、名称和现有签名保持不变。

## 测试

新增回归包含：

- 有修改的普通表单关闭确认、继续编辑、放弃后重新打开为空。
- 系统返回依次从工具页返回事件详情、列表、流水。
- 普通表单保存状态重建后仍保留输入，保存只回调一次。
- 公共表单在数据库暂未加载时恢复金额和参与者。
- UTF-8 备份容量边界：恰好 20 MiB 可以读，超出被拒绝；超限导出被拒绝。
- 连续修改公共费用后，事务快照内的个人流水与本人分摊额一致。
- 1 万笔、5 万笔独立测试账本读取、统计筛选、备份编码/解码往返。
- 金额校验的零、负数、上限和超限边界。

状态重建测试使用 Compose 的 StateRestorationTester；它验证保存状态恢复，不等同于所有品牌手机的真实进程回收。设备测试使用独立临时数据库，不清空实际账本。

## 限制与安装

- 20 MiB 是明确容量上限，超限不会生成“成功但无法恢复”的备份；无限规模的流式备份尚未实现。编码仍使用 JSON 对象树，并非恒定内存流式处理。
- 尚未验证各品牌手机的后台回收行为和真实帧率；不将模拟器结果等同于真机验证。
- Android Lint 原有的 SDK/构建版本提示和启动图标警告暂未通过升级依赖或更换图标处理，避免扩大本次兼容性改动。
- 签名备份和跨电脑更新说明见 [安装文档](INSTALL-ANDROID.md)。未生成新签名，也未将密钥加入 Git。
- 安装包位于 `app/build/outputs/apk/debug/SPSir.apk`。更新前导出备份，直接覆盖安装，不先卸载。
